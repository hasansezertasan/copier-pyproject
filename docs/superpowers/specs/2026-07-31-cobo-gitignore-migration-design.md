# Design: Migrate `.gitignore` generation from gibo → cobo

- **Date:** 2026-07-31
- **Status:** Approved (design)
- **Scope decision (confirmed with maintainer):** Regenerate **+ lockfile**, and add
  cobo to **generated projects too**.

## Problem

`template/.gitignore.jinja` is currently produced by
[`gibo`](https://github.com/simonwhitaker/gibo): it stacks the
`Global/macOS`, `Global/Windows`, `Global/Linux`, `Global/VisualStudioCode`, and
`Python` boilerplates from `github/gitignore`, pinned by a commit in `###`-prefixed
provenance headers, followed by a hand-written `### Generated by the author` section.

`gibo` was run ad hoc; there is no drift detection. Two project-specific overrides were
hand-injected **inside** the boilerplate:

- `template/.gitignore.jinja:123-126` — `{%- if include_freezer %}` → `!{{github_repo_name}}.spec`
  (un-ignore the committed PyInstaller spec) inserted right after `*.spec`.
- `template/.gitignore.jinja:274-277` — `{% if include_c_extensions %}` →
  `/src/{{github_repo_name}}/_c_extension.c` inserted after `cython_debug/`.

We migrate to [`cobo`](https://github.com/hasansezertasan/cobo) (the maintainer's own
"copy boilerplates" tool, v0.3.0), which fetches the **same** `github/gitignore`
templates but adds a lockfile + `check`/`sync` drift detection that gibo lacks.

## How cobo works (verified empirically)

- `cobo gitignore dump <names…> --out <file> --lock` writes the concatenated boilerplate
  into `<file>` inside a **fenced region** and records provenance in `cobo.lock`:
  ```
  # >>> cobo:begin >>>
  # Generated by cobo (github.com/hasansezertasan/cobo)
  # gitignore/macOS@57286c3 — https://raw.githubusercontent.com/github/gitignore/<sha>/Global/macOS.gitignore
  …
  # <<< cobo:end sha256=<hash-of-region> <<<
  ```
- Each boilerplate gets its own `# Generated by cobo …` + `# gitignore/<Name>@<short> — <url>`
  two-line header (single `#`, replacing gibo's `###`).
- `cobo.lock` (TOML) records, per fragment: `path`, `source = "gitignore"`, and one
  `[[fragment.files]]` per boilerplate with `name`, `path`, `commit`, `blob`.
- Content **after** the `# <<< cobo:end … <<<` fence is **preserved** by `cobo sync`
  and ignored by `cobo check` — verified: appending an author section then running
  `cobo sync` left it untouched.
- `cobo check` compares the fenced region against the **local clone** of
  `github/gitignore`; `cobo update` (network) refreshes that clone.

## Key constraint → restructure

cobo hash-verifies the fenced region, so it must contain **verbatim** boilerplate.
The two interleaved jinja conditionals therefore **move out of the fence into the author
section**, below the end fence. This is functionally equivalent:

- `!{{github_repo_name}}.spec` still appears **after** the `*.spec` pattern (which lives
  inside the fenced Python boilerplate), so git's last-match-wins negation still holds.
- `/src/{{github_repo_name}}/_c_extension.c` is a plain ignore; order is irrelevant.

It also improves separation of concerns: upstream boilerplate stays pristine/verifiable;
project overrides are unambiguously the author's.

## Target `template/.gitignore.jinja` shape

```jinja
# >>> cobo:begin >>>
# Generated by cobo (github.com/hasansezertasan/cobo)
# gitignore/macOS@<sha> — <url>
…macOS…
…Windows…Linux…VisualStudioCode…Python (verbatim, NO jinja inside)…
# <<< cobo:end sha256=<hash> <<<

### Generated by the author
{%- if include_freezer %}
# ...except the committed PyInstaller spec the release workflow builds from.
!{{github_repo_name}}.spec
{%- endif %}
{%- if include_c_extensions %}
# Cython-generated C source (regenerated from _c_extension.pyx at build time)
/src/{{github_repo_name}}/_c_extension.c
{%- endif %}
src/**/_version.py
mise.local.toml
```

## Components

### A. skipjack (this template repo) — manage `template/.gitignore.jinja`

- Root **`cobo.lock`** with `[[fragment]] path = "template/.gitignore.jinja"`, pinning the
  five boilerplates. `cobo check` (from repo root) validates the fenced region of the
  `.jinja` file; the author section (with jinja) sits outside the fence and is ignored.
- Regeneration is a documented maintainer command (see CLAUDE.md update below).

### B. Generated projects — always-included (no copier toggle)

cobo becomes standard tooling like mise/renovate/commitizen — **no** `copier.yml` option.

- **`template/cobo.lock`** (static file, copied verbatim by copier) with
  `[[fragment]] path = ".gitignore"`. Because the rendered `.gitignore` fence region is
  byte-identical to cobo's output, a fresh scaffold passes `cobo check`.
- **`template/mise.toml.jinja`**:
  - `[tools]` → add `"pipx:cobo" = "<pinned>"` (Renovate-tracked, same style as the
    existing `aqua:`/`npm:` tools).
  - `[tasks.gitignore-check]` → `mise exec -- cobo update && mise exec -- cobo check`
    (on-demand; network allowed here).
- **`template/.gitattributes.jinja`** → mark `cobo.lock` as linguist-generated
  (`cobo.lock linguist-generated=true`), matching `uv.lock`/`_version.py` handling.
- **taplo / editorconfig / validate scope** → ensure `cobo.lock` (2-space TOML) passes
  the `style` suite. Verify `taplo` does not reformat cobo's output; if it does, add
  `cobo.lock` to the taplo exclude or align formatting. Confirm the 2-space `.editorconfig`
  glob covers `.lock` or that `cobo.lock` is excluded like other generated files.

### C. Drift check — weekly cron only (non-blocking)

New static workflow **`template/.github/workflows/gitignore-drift.yml.jinja`**, modeled on
`docs-linkcheck.yml`:

- Triggers: weekly `schedule` + `workflow_dispatch` only (**not** `pull_request`, **not**
  in the `check` aggregation gate). Rationale: `cobo check` needs a network `cobo update`;
  network-flaky checks stay out of the blocking gate (same posture as `docs-linkcheck` and
  `check-security`'s cron).
- Steps: checkout (`persist-credentials: false`) → `jdx/mise-action` (SHA-pinned) →
  `mise exec -- cobo update` → `mise exec -- cobo check`. Fails the run on drift so the
  maintainer is notified, but never blocks a PR.
- Hardened to the repo's zizmor posture: `permissions: {}` top-level, least-privilege
  per-job (`contents: read`), no untrusted `${{ }}` in `run:`.
- **No** blocking prek/CI hook (explicitly rejected in design review).

### D. Documentation

- **`CLAUDE.md`** — replace gibo mentions; document the cobo regeneration command
  (`cobo gitignore dump macOS Windows Linux VisualStudioCode Python --out template/.gitignore.jinja --lock`
  then re-append the author section, or `cobo sync`), the always-included cobo tooling in
  the generated-project list, the new `gitignore-drift.yml` workflow, and the
  `[tasks.gitignore-check]` mise task.
- **`README.md`** — mention cobo under generated-project tooling.
- **`docs/adr/012-cobo-for-gitignore-generation.md`** — new ADR recording: why cobo over
  gibo (own tool, lockfile/drift detection), the fence + author-section split, always-included
  (no toggle), and weekly-cron (not blocking) drift check.

## Regeneration procedure (canonical)

From the skipjack repo root:

1. `cobo update`
2. Regenerate the fenced region of `template/.gitignore.jinja` (dump the five boilerplates
   with `--out template/.gitignore.jinja --lock`, which rewrites the fence + root
   `cobo.lock` and preserves the author section below the fence).
3. Produce/refresh `template/cobo.lock` for generated projects (same five files, but
   `path = ".gitignore"`) — generated by dumping into a scratch `.gitignore` and copying the
   lock with the path adjusted.
4. `copier copy --data-file .example-input.yml --defaults . example/ --force`
5. `cd example && uv run --locked tox run -e style` (confirms `cobo.lock`/`.gitignore` pass
   taplo/editorconfig/actionlint/zizmor).
6. In a scaffold with cobo installed: `cobo check` → "up to date".

## Verification

- `git diff` of the rendered `example/.gitignore` shows only header-format changes
  (`###` → `#`, cobo provenance) and the relocated conditionals — no ignore-pattern
  semantics change.
- Fresh scaffold: `cobo check` reports the `.gitignore` fragment **up to date**.
- Render with `include_freezer=true` and `include_c_extensions=true`; confirm
  `!{{repo}}.spec` and `_c_extension.c` appear in the author section and the negation works.
- `tox run -e style` green in `example/`.
- `gitignore-drift.yml` passes `prek run zizmor --all-files` and `actionlint`.

## Out of scope

- No change to `copier.yml` (cobo is unconditional tooling, no toggle).
- No change to the set of boilerplates (still macOS/Windows/Linux/VisualStudioCode/Python).
- No blocking prek/CI drift hook.
- skipjack's own root `.gitignore` (not the template) is untouched.
